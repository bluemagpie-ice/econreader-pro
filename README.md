# EconReader-Pro｜经济学论文研读助手

EconReader-Pro 是面向经济学本科生、研究生及科研人员的论文研读 Skill。根据论文的主要研究范式选择分析框架，帮助读者理解研究问题、论证方法、主要结论及贡献，并追溯关键判断的原文依据。

默认直接在对话中提供可独立阅读的速读报告；根据用户需求继续精读、解释模型或比较多篇论文。

## 分析框架

| 类型 | 分析重点 |
|---|---|
| A 实证研究 | 数据与样本、变量、估计对象、识别策略、主要结果，以及实际开展的机制、稳健性和异质性分析 |
| B 数理理论 | 主体与信息结构、假设、目标与约束、均衡或激励条件、核心命题及经济直觉 |
| C 制度、思想史与非形式化理论 | 概念语境、论证链条、制度与历史论据、解释范围 |
| D 文献综述 | 覆盖范围、主题与观点结构、共识与分歧、观点归属及作者综合 |
| E 计量与统计方法学 | 方法原理、识别与统计条件、误用来源、改进建议及适用边界 |

采用“主类型＋辅助模块”：分类决定报告骨架，实际内容决定补充分析。不会仅凭公式判定为理论论文，也不会为所有实证论文机械套用 DID 模板。

## 使用方式

在支持目录式 Skill 的环境中，按该平台的安装要求加载本仓库中的 `SKILL.md` 及 `references/`。`agents/openai.yaml` 提供可选的 Codex 界面元数据，不是核心执行规则的依赖。

支持按名称调用的环境可使用：

```text
请使用 econreader-pro 研读我提供的论文，先给出带原文依据的速读报告。
```

也可以直接说明需求：

```text
我需要准备课堂汇报，请解释这篇论文的问题、方法和核心结论。
请精读本文的模型设定，解释目标函数、约束与核心命题之间的关系。
请逐步解释命题 2 的证明，区分原文步骤和补充说明。
请比较这两篇论文的研究问题、方法和结论，并说明是否可以直接比较。
```

请同时提供论文原文或可读文本；如有附录，建议一并提供。主文和附录视为同一篇论文。

### 默认交互

- 首答先说明论文定位，再输出完整速读，不等待背景问卷。
- 报告末尾提供与本文相关的深入阅读入口；用户可补充阅读目的和数学、计量基础。
- 精读默认解释到模型或论证结构层面；逐步证明在用户指定命题后展开。
- 先还原作者论证，再给简短评价；系统性批判和 AI 研究选题建议按需开启。
- 多篇默认按“逐篇简述 → 对比矩阵 → 重要关系与分歧 → 按需精读”组织。
- 默认在对话中输出 Markdown；下载文档需用户提出，并以所在平台的实际文件生成能力为准。

## 证据与可靠性

关键事实尽可能标注原文页码、章节、表图、方程或附录位置，区分 `[作者陈述]`、`[AI归纳]` 与 `[AI建议]`。

缺失信息分别标记为“原文未说明”“当前材料无法核实”或“解析不可靠”，并说明检查范围。相关性、模型分解与机制一致性证据不自动视为因果证明；有限文献也不足以确认整个领域的研究空白。

Skill 不包含独立的 PDF/OCR 引擎。公式、表格或扫描页能否可靠读取，取决于运行环境的模型及工具能力；无法核实时应明确说明，不补造。

## 目录结构

```text
econreader-pro/
├── SKILL.md                  # 主入口和路由
├── references/               # 五类工作流、证据规则、输出规范和参考示范
├── agents/openai.yaml        # 可选界面元数据
├── scripts/build_package.py  # 生成模块化包和单文件版
├── evaluation/               # 分类校准记录及行为验收清单
├── README.md
└── .gitignore
```

本地 `tests/` 中的论文、`submission/` 中的生成物、评测运行输出及临时文件不纳入版本控制。`references/` 中的已有分析范例保留用于表达校准，不作为新论文的事实来源。

## 生成交付文件

构建脚本仅使用 Python 标准库，在仓库根目录运行：

```bash
python -X utf8 scripts/build_package.py
```

生成：

- `submission/econreader-pro-modular.zip`：包含主入口、参考模块及可选元数据。
- `submission/econreader-pro-single-file.md`：将执行规则内联，适用于需要单文件指令的环境，不包含示范案例事实。

脚本检查内部文件链接和 ZIP 完整性。实际导入目录、文件大小限制和触发方式须按目标平台要求确认；生成成功不等于平台兼容性已经验证。
